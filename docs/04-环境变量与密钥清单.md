# 两面 · 环境变量与密钥清单

> 技术文档 4/4 · 外部 Key 与配置项的单一事实源
> 依据：知乎 Skill 0.5.3-beta（2026-09-04 资料）+ 本项目后端文档 §3/§8
> 本文件只写**变量名、用途、申请方式与安全边界**，不写任何真实值。

---

## 1. 总表

| 变量 | 归属 | 必填 | 用途 |
|---|---|---|---|
| `ZHIHU_ACCESS_SECRET` | server | ✅ | 开放平台调用方凭证。搜索 / 热榜 / 直答 / 用户数据**全部**用它做 Bearer 鉴权 |
| `ZHIHU_OAUTH_APP_ID` | server | 条件 | 增强层：构造知乎授权跳转地址（活动页创建项目后分配） |
| `ZHIHU_OAUTH_APP_KEY` | server | 条件 | 增强层：后端换取 OAuth access token，**保密** |
| `ZHIHU_OAUTH_REDIRECT_URI` | server | 条件 | 增强层：授权回调地址，必须与活动页登记值**完全一致**（含协议、域名、路径、尾部斜杠） |
| `ZHIHU_ZHIDA_MODEL` | server | 可选（默认 `zhida-thinking-1p5`） | 直答模型档位：`zhida-fast-1p5` / `zhida-thinking-1p5` / `zhida-agent` |
| `DEEPSEEK_API_KEY` | server | ✅（当前 `providers.yaml` 绑定） | 提取 / 归并 / 取向 Agent 的主力模型 |
| `GLM_API_KEY` | server | 建议 | fallback 模型 + 直答降级时的 `summaryFallback` |
| `QWEN_API_KEY` | server | 可选 | 取向 Agent 的第二备选 |
| `TZ` | server | ✅ | 固定 `Asia/Shanghai`（代码内另有时区兜底，双保险） |
| `ZHIDUAN_DB_PATH` | server | 可选（默认 `./data/two-sides.db`） | SQLite 单文件路径 |
| `SERVER_PORT` | server | 可选（默认 `3000`） | Hono 监听端口，Caddy 反代到此 |
| `INTERNAL_TOKEN` | server | 条件 | 外部 `crontab` 调 `/internal/pregenerate` 时的校验 token（自生成随机串） |
| `ANALYSIS_RETRY_COOLDOWN_SEC` | server | 可选（默认 `60`） | `failed` 后再试的冷却窗口，防连点打穿额度 |
| `ANALYSIS_JOB_TIMEOUT_SEC` | server | 可选（默认 `180`） | 单 job 总时限，超时置 `timeout` |
| `LLM_RPM_LIMIT` | server | 可选（默认 `60`） | 全局令牌桶，防打爆 LLM 与知乎限频 |
| `PREGENERATE_TOP` | server | 可选（默认 `30`） | 每日 00:30（Asia/Shanghai）进程内 cron 预生成的热榜题数 |
| `PROVIDERS_CONFIG` | server | 可选（默认 `config/providers.yaml`） | 服务商与 Agent 绑定配置路径 |
| `VITE_API_MODE` | web | 开发期 | `mock` / `live` |
| `VITE_API_BASE` | web | 部署 | 默认 `/api/v1` |

**条件** = 仅当增强层（OAuth）启用时需要；凭证未获批时整层不启用，不影响主流程。

## 2. 知乎侧三种凭证：不要混

这是最容易搞错的一点——它们是三样独立的东西，不是同一个 key 的不同名字：

| 凭证 | 谁发 | 干什么 | 出现位置 | 能进前端吗 |
|---|---|---|---|---|
| **Access Secret** | 开放平台个人中心 | 鉴权"调用方"；搜索/热榜/直答/用户数据每次请求都要带 | `Authorization: Bearer` | ❌ |
| **OAuth App ID** | 黑客松活动页（创建项目后） | 标识第三方应用，构造授权地址 | 授权跳转 URL 参数 | ✅ 可公开 |
| **OAuth App Key** | 黑客松活动页 | 后端换 token | 仅后端表单字段 | ❌ |
| **OAuth access token** | 用户授权后换取 | 代表某个已授权用户 | `X-OAuth-Token` | ❌ |

关键句：**App Key 不是 Access Secret，也不能当 Access Secret 用**；反过来，用户数据接口需要"两个头一起发"：

```http
Authorization: Bearer <ZHIHU_ACCESS_SECRET>
X-OAuth-Token: <用户 OAuth access token>
X-Request-Timestamp: <秒级 Unix 时间戳>
```

不传 `X-OAuth-Token` 时，接口返回的是 Access Secret 所属账号**本人**的数据——我们只在开发自测时用得到这个模式。

## 3. 申请入口

| 凭证 | 入口 | 备注 |
|---|---|---|
| Access Secret | <https://developer.zhihu.com/profile> → 「申请新 Access Secret」 | 单个账号最多 20 个；**同账号下所有 Secret 共享同一额度池**；删除后不可恢复 |
| App ID / App Key | 活动页 → 我的项目 → 创建项目后分配 | 用 OAuth 必须在活动页登记回调地址 |
| 直答额度提额 | 邮件 <openplatform@zhihu.com> | 工作日 09:00–18:00，1 个工作日内回复 |

## 4. 外部 LLM

`config/providers.yaml` 里只写 **变量名**，不写值：

```yaml
- name: deepseek
  apiKeyEnv: DEEPSEEK_API_KEY   # 值从 env 注入，yaml 里永远只有变量名
  models: [deepseek-chat, deepseek-reasoner]
```

新增服务商时：加 `apiKeyEnv` → 在部署环境注入同名变量 → 在 `agents.*` 里绑定。**不要在 yaml 或代码里出现密钥字面量。**

## 5. 额度对照（当前邀测，每日自然日）

| 能力 | APIID | 日额度 | 我们的日消耗 |
|---|---|---:|---|
| 知乎搜索 | `zhihu_search` | 5,000 | ~90（30 题 × 3 变体）+ 懒生成 |
| 知乎热榜 | `hot_list` | 100 | 1 |
| 知乎直答 | `zhida_openai` | 100 | 30（预生成）+ 懒生成，**最紧的一项** |
| 用户数据 | `user_data` | 10,000 | 仅增强层，按需 |
| 全网搜索 | `global_search` | 5,000 | 0（我们不用，会丢知乎专属信号） |
| 知识库 | `knowledge` | 500 | 0 |
| 小工具 | `tools` | 10 | 0 |

`GET /api/v1/quota?APIIDs=zhihu_search,hot_list,zhida_openai` 可查剩余额度，**查询本身不消耗额度**——`/health` 就是靠它报余量。

错误码映射：`30001` 频率限制 → `zhihu_error`（可重试）；`30002` 配额耗尽 → `quota_exhausted`（**不可重试**，次日恢复）。

## 6. 安全红线

1. 四个涉密变量（`ZHIHU_ACCESS_SECRET`、`ZHIHU_OAUTH_APP_KEY`、OAuth token、各 LLM key）**只存在于部署平台的 Secret 或本地 `.env`**
2. `.env` 必须进 `.gitignore`；仓库里只提交 `.env.example`（写变量名、写占位）
3. 绝不进入：前端代码与响应、URL、日志、错误信息、截图、演示视频、Agent 输出
4. 诊断信息只展示：来源（env/密钥链）、是否已配置、长度、SHA-256 短前缀
5. 提交前必查（黑客松提交检查项之一）：仓库、前端响应、日志、截图、视频里没有凭证
6. 泄露处理：Access Secret 在个人中心删除并重新申请（**删除不可恢复**）；LLM key 在服务商控制台轮换
7. 环境变量会覆盖系统密钥链；容器/CI 场景直接注入 `ZHIHU_ACCESS_SECRET` 即可，不要用文件兜底

## 7. 最小启动集

**本地开发（不含增强层）**

```bash
ZHIHU_ACCESS_SECRET=...      # 必填，否则搜索/热榜/直答全部 AUTH_REQUIRED
DEEPSEEK_API_KEY=...         # 管线主力模型
TZ=Asia/Shanghai
VITE_API_MODE=mock           # 前端先不联后端
```

**部署（docker-compose，不含增强层）**

```bash
ZHIHU_ACCESS_SECRET / DEEPSEEK_API_KEY / GLM_API_KEY
TZ=Asia/Shanghai
SERVER_PORT=3000
ZHIDUAN_DB_PATH=/app/data/two-sides.db
INTERNAL_TOKEN=<随机串>      # 若用外部 crontab 触发预生成
```

**启用增强层时追加**

```bash
ZHIHU_OAUTH_APP_ID / ZHIHU_OAUTH_APP_KEY / ZHIHU_OAUTH_REDIRECT_URI
```
